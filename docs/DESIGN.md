# 设计说明：一致判定与并发/失败语义

本文说明各需求点在实现上的关键取舍，便于审查“为什么在不同入口结果一致且可解释”。

## 1. 单一判定入口（Single Choke Point）

所有 HTTP 路由都不自行实现鉴权/限流，而是统一调用
`app/api/deps_auth.authorize()`：

```
Bearer 解析 → AuthService.verify_access_token → RateLimitService.acquire → 业务服务
```

领域服务（`AuthService/ConsentService/...`）也可被测试直接调用，二者共用同一套错误码
（`ErrorCode`）与同一份审计写入。因此“令牌签名错误”无论是出现在资源接口、同意接口
还是回调接口，返回的 `error.code` 完全一致。

## 2. 判定顺序与错误码互斥

凭证校验固定顺序：缺失 → 未知租户 → 密钥错误 → 已吊销 → 已过期。
令牌校验固定顺序：缺失 → 结构错误 → 算法白名单 → 密钥（未知/退役）→ 签名 →
过期 → 凭证吊销/过期 → 租户不匹配 → 作用域。

先做算法白名单判定、再取密钥，可确保 `none` 等伪造令牌不会因为“查无此钥”而被误报成
`token_key_unknown`，三类安全失败（算法/签名/退役）错误码严格互斥。

## 3. 密钥轮换窗口

- 新密钥以 `ACTIVE` 加入后即用于**新签发**；验签时 ACTIVE 与“尚未退役”的旧密钥都可用。
- 轮换分两步（add 新钥 → retire 旧钥），并存期内旧令牌保持有效，避免轮换瞬间误拒。
- `retire` 是显式状态位（`KeyState.RETIRED` + `retired_at`），验签解析到该 kid 时
  单独抛 `TOKEN_KEY_RETIRED`，与“kid 不存在（UNKNOWN）”“签名错误（BAD_SIGNATURE）”
  在代码路径上就是三个不同分支。

## 4. 同意状态机与历史完整性

- 合法流转表 `ALLOWED_TRANSITIONS` 是唯一事实源；任何不在表内的变更直接拒绝，且在拒绝
  前先写一条 `consent_transition_denied` 审计。
- `_transition()` 在存储锁内：深拷贝旧状态 → 修改内存对象 → 写审计；若审计抛错，则用
  深拷贝恢复，保证“状态变更”和“审计可追溯”同时成功或同时失败。
- `history` 仅 `append`，从不按 consent_id 重建覆盖；撤销原因、授权/撤销时间戳独立保留。
- 资源访问在判定 REVOKED/EXPIRED/未授权/超期/作用域/账户不匹配时分别抛不同错误码，并为
  每次拒绝落审计。

## 5. 并发正确性

- 进程内 `threading.RLock` 保护所有内存表。计数自增（限流/配额）只在锁内发生，且限流与
  配额在同一临界区一起自增，杜绝“限流通过但配额未计”之类的窗口。
- 被拒绝路径**在锁内直接不自增**，所以拒绝天然不耗额度，无需事后补偿。
- 回调触发的“查重 + 建事件 + 审计 + 首次投递”在同一把锁内原子完成（模拟调用方为纯内存
  操作，锁内执行安全），因此并发重复触发只有一个胜出者会真正投递。
- 每次投递还有 `in_flight` 重入保护与“退避时间未到”保护，避免重试线程互相串状态。

> 真实分布式部署需要把锁/窗口换成 Redis/数据库原子操作，接口契约（错误码、不耗额度、
> retry_after）保持不变。

## 6. 退避与死信

- 退避只更新 `next_attempt_at`，不占用线程睡眠；`deliver_until_settled` 配合可注入时钟
  推进时间，因此测试是确定性的、无需真实等待。
- `attempt_history` 逐次记录 `attempt/ok/error/result/backoff`，DEAD 终态保留全部失败
  原因供查询；DELIVERED 与 DEAD 都是终态，后续触发/投递不会再改写。

## 7. 审计脱敏与失败语义

- 脱敏在写入前递归处理嵌套 dict；`AuditLog.write()` 先追加文件（fsync）再写入内存列表，
  文件失败时内存不会出现“已审计”假象。
- fail-closed（默认）抛 `AuditWriteError`，业务服务在状态机流转点捕获并回滚；在“创建”
  场景则删除未完成对象，保证失败请求无残留。

## 8. 规模/超时中间件

- `LimitsMiddleware` 先用 `Content-Length` 做 O(1) 预检，再对分块 body 累计校验，超限抛
  内部哨兵，最终返回 413，整条请求不进入路由，故不产生业务状态、不消耗配额。
- 超时由 `asyncio.wait_for` 包裹整个 ASGI 应用；中间件自身不创建跨请求资源，存储/审计
  的文件句柄都在 with 块内关闭。

## 9. 本地存储与可复现测试

- `Storage` 为内存表 + `os.replace` 原子 JSON 快照；默认不落盘，测试零 IO。
- `Clock` 以偏移量模拟时间推进，所有“过期/退避”测试快速且确定。
- `SimulatedCaller` 按 `(event_id, url)` 维护瞬时失败计数，模拟“同一目标先失败后恢复”，
  且不同事件互不污染。
